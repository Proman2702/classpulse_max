# Проверка ClassPulse на трёх тестовых аккаунтах

Этот сценарий использует **три уже зарегистрированных тестовых аккаунта**. Пароль для всех трёх: **`ClassPulse2026`** (вводить без обратных кавычек). 30.09.2026 пароль восстановлен и вход каждого аккаунта проверен на подключённом Supabase.

| Роль | Email для входа | Ник в приложении |
|---|---|---|
| Ученик | `student@classpulse.test` | `studenttest` |
| Учитель | `teacher@classpulse.test` | `teachertest` |
| Психолог | `psychologist@classpulse.test` | `psychologisttest` |

Это общие демонстрационные аккаунты: не используйте этот пароль для личных профилей. Новых пользователей создавать не нужно. `npm run seed` **не запускать**: он создаёт других учеников и заранее заполняет класс, ответы и обращения.

Исходное состояние этой тройки при проверке 30.09: у ученика нет ответов, у трёх профилей нет заметок, записей и жалоб; **ученик уже добавлен в класс тестового учителя** (одна связь, без отметки «на контроле»). Поэтому учитель сначала видит `0 / 1`, а не `0 / 0`. В подключённой рабочей базе есть и другие старые профили — полный состав базы описан в [ARCHITECTURE.md](ARCHITECTURE.md). Числа ниже относятся к этой тройке; если после проверки появились новые данные, сравнивайте их с текущим состоянием и не удаляйте чужие записи.

Открывать приложение можно из бота ClassPulse в MAX → «Открыть ClassPulse», на https://classpulse-max.vercel.app или локально через `npm run dev:miniapp`. Для проверки получения уведомлений каждому из трёх профилей нужен **свой аккаунт MAX**: привязка одного MAX-аккаунта к другому профилю переносит её, а не создаёт три независимых получателя.

Удобный порядок: войти учителем и убедиться, что его единственный тестовый ученик ещё не отвечал; затем пройти опрос и поддержку за ученика, проверить класс и обращения за специалистами. Чтобы отдельно проверить добавление по нику, учитель может убрать **только этого тестового ученика** из класса и сразу добавить обратно. Перед проверкой уведомлений войти каждым профилем через бота в MAX и убедиться в статусе «Подключены».

## 2. Ученик: опрос дня

Тестовый ученик уже связан с тестовым учителем. Поэтому его низкая оценка видна в этом классе и может вызвать уведомление. Если для проверки добавления ученик временно убран из класса, сначала добавьте его обратно (раздел 4).

| Шаг | Ожидаемый результат |
|---|---|
| Войти существующим тестовым аккаунтом ученика | Вкладка «Сегодня»; бот обращается к ученику по нику из профиля и задаёт вопрос о дне |
| Нажать «😕 Тяжело» (2/5) | Ответ справа; бот спрашивает о причинах |
| Выбрать, например, «Усталость» и «Конфликт» → «Дальше» | Причины показаны сообщением; бот предлагает необязательный комментарий |
| Ввести нейтральный тестовый комментарий «Проверка опроса» → отправить | Ответ сохранён, появилась галочка; бот благодарит и предлагает психолога |
| «Записаться к психологу» | Открывается вкладка «Поддержка» с формой записи к психологу |
| Вернуться в «Сегодня» → «Переголосовать», выбрать 4/5 и отправить | Ответ за **тот же день** обновился: у ученика один ответ, у учителя после обновления `1 / 1` и оценка 4/5; второй ответ за день не возник |
| Закрыть и снова открыть приложение | Сессия восстановлена, показан завершённый диалог с последним ответом за сегодня |

Для проверки уведомления учителю о плохом дне откройте сообщение бота **до** переголосования на 4/5. Проверка истории пяти разных оценок требует ответов в разные дни: на пустом аккаунте её нельзя считать пройденной после одного опроса.

## 3. Ученик: поддержка и профиль

Все обращения создаёт один тестовый ученик. Получателями выступают существующие тестовые учитель и психолог. Используйте нейтральные учебные формулировки, не реальные обвинения.

| Шаг | Ожидаемый результат |
|---|---|
| «Записаться к психологу», выбрать единственного психолога, указать тему «Проверка записи» и удобное время → «Записаться» | Успех; одна новая запись в «Мои записи» со статусом «Ждёт ответа»; эту же запись видит психолог |
| Попытаться отправить форму с пустой темой | Ошибка «Напишите пару слов о теме разговора», новая запись не создаётся |
| «Записаться к учителю» → тема «Проверка обращения к учителю» → «Записаться» | Ещё одна запись видна ученику и учителю, но не психологу |
| «Анонимная жалоба» → получатель психолог → «Другое» → нейтральный текст «Проверка анонимного обращения» → «Отправить анонимно» | Жалоба видна в «Мои жалобы» как «Новая»; психолог видит её текст, но не автора |
| При необходимости повторить жалобу с получателем-учителем | Жалобу видит учитель; психолог её не видит |
| «Чат с учителем в MAX» до добавления ссылки учителем | Имя учителя видно после связи с классом; «Написать» неактивна без ссылки в профиле учителя |
| Учитель указывает в своём профиле настоящую ссылку на свой профиль MAX | У ученика после обновления «Написать» становится активной и открывает MAX |
| «Профиль»: попробовать ссылку `https://vk.com/test`, затем сохранить свою настоящую ссылку MAX | Чужой домен отклонён; ссылка вида `https://max.ru/...` сохраняется с сообщением «Сохранено» |

## 4. Учитель: единственный ученик в классе

| Шаг | Ожидаемый результат |
|---|---|
| Войти учителем до ответа ученика | «Мой класс · 1 ученик», «Ответили сегодня 0 / 1», средняя оценка `—`; сводка недоступна, единственный ученик имеет состояние «Нет данных» |
| Если нужно проверить пустой класс: убрать тестового ученика из карточки | `0 / 0`, приглашение и добавление по нику; ответы ученика при этом не удаляются |
| «+» → ник `studenttest` после временного удаления связи | Ученик снова в классе; до его первого опроса `0 / 1`, состояние «Нет данных» |
| Открыть карточку ученика до опроса | Сообщение, что ученик пока не отправлял состояние; заметок нет |
| После ответа ученика 2/5 обновить класс | `1 / 1`, средняя 2/5, единственный ученик «Требует внимания»; карточка показывает последнюю оценку, причины и комментарий |
| «Составить сводку» после ответа | Загрузка «Читаю ответы…», затем непустой текст по ответу без имени ученика; результат зависит от GigaChat и не обязан повторять конкретные заголовки |
| Поиск по части ника этого ученика, затем по несуществующему нику | Сначала одна карточка, затем «Ничего не найдено» |
| «Взять на контроль» → фильтр «⭐ На контроле» → снять отметку | Сначала одна отмеченная карточка, после снятия фильтр пуст |
| Добавить личную заметку в карточке → удалить её | Заметка появляется и исчезает; ученик и психолог её не видят |
| «+» → несуществующий ник; затем ник уже добавленного ученика | Понятные ошибки «Ученик с таким ником не найден» и «Этот ученик уже в классе»; число учеников остаётся `1` |
| Сортировка «По состоянию» / «По имени» | Переключатель работает, карточка остаётся на месте. Порядок нескольких учеников на этой тройке проверить нельзя |
| После переголосования ученика на 4/5 | Средняя оценка за сегодня 4/5, один ответ и состояние «Хорошее», если это единственная оценка ученика |

«Нестабильное», порядок нескольких учеников и история из пяти дат требуют нескольких дней или отдельного изолированного набора данных. Не записывайте их как проверенные на одном пустом ученическом профиле.

## 5. Обращения: учитель и психолог

| Шаг | Ожидаемый результат |
|---|---|
| До действий ученика открыть «Обращения» учителя и психолога | У выбранных пустых профилей нет адресованных им записей и жалоб |
| После записи к учителю открыть его «Обращения» | Одна новая запись от тестового ученика; психолог эту запись не видит |
| Принять запись учителем | Статус «Принята»; бейдж новых обращений уменьшается; ученик видит новый статус |
| Открыть «Обращения» психолога после записи к психологу | Только адресованная ему запись от этого ученика; можно принять или отклонить |
| Психолог принимает свою запись | Статус «Принята» у психолога и ученика; затем доступно «Разговор состоялся» |
| Психолог открывает адресованную ему жалобу | Нет имени автора; «Новая» становится «Прочитана»; «Отметить решённой» переводит в «Решена» |
| Ученик снова открывает «Поддержку» | Его записи и жалобы показывают новые статусы |
| При отправке второй жалобы учителю открыть «Жалобы» у обоих специалистов | Каждый видит только обращение, адресованное ему; автор не указан |

Сортировку жалоб по разной срочности можно проверить только при наличии хотя бы двух жалоб **одному** получателю с разными оценками GigaChat. В этом коротком сценарии достаточно проверить бейдж и приватность одной жалобы.

## 6. Уведомления и приглашение через MAX

Нужны настроенные секреты и `private.app_config` (см. README). Каждый из трёх пользователей должен открыть ClassPulse из бота **под своим MAX-аккаунтом** и войти в соответствующий профиль ClassPulse: в «Профиле» должно быть «Уведомления в MAX: Подключены». В обычном браузере без запуска из MAX этот статус сам не подключится.

| Шаг | Ожидаемый результат |
|---|---|
| Связанный с классом ученик впервые ставит 1–2/5 | Учителю приходит сообщение бота о плохом дне с кнопкой «Открыть ClassPulse» |
| Ученик записывается к психологу | Психологу приходит сообщение о новой записи с той же кнопкой |
| Психолог принимает запись | Ученику приходит сообщение о принятии |
| Ученик отправляет жалобу психологу | Психологу приходит сообщение о новой анонимной жалобе **без имени автора и текста жалобы** |
| Психолог решает жалобу | Ученику приходит сообщение о том, что жалобу рассмотрели |
| Учитель → «Класс» → «Пригласить учеников через MAX» | Открывается панель «Отправить в MAX» со ссылкой на бота; в обычном браузере доступно системное меню или копирование. Для проверки панель можно закрыть без отправки в настоящий чат |

Если один и тот же аккаунт MAX по очереди открывает разные профили ClassPulse, привязка переносится к последнему: по такой схеме нельзя подтвердить доставку всем трём ролям одновременно. При ошибке MAX сохранение ответа и обращения должно продолжать работать; автоматического повтора неотправленных уведомлений пока нет.

## 7. Ошибки и устойчивость

| Ситуация | Ожидаемый результат |
|---|---|
| Ввести неверный пароль одного из существующих аккаунтов | «Неверный email или пароль», без входа в приложение |
| Открыть вкладку регистрации, не создавая четвёртый аккаунт | Доступны роли ученика, учителя и психолога |
| Отключить сеть перед отправкой опроса | Сообщение «Нет соединения. Проверьте интернет»; ответ остаётся в форме, после восстановления сети его можно отправить |
| GigaChat недоступен | Сводка показывает ошибку и позволяет повторить; жалоба сохраняется со срочностью «Обычная». Сбой нужно моделировать только на отдельном стенде, не отключать рабочий сервис ради проверки |
| Системная кнопка «Назад» MAX при открытой шторке | Шторка закрывается; на физическом мобильном клиенте это ещё нужно проверить отдельно |
| Тёмная тема устройства | Интерфейс переключается автоматически |

## 8. Проверка анонимности (для технической комиссии)

В интерфейсе психолога или учителя жалоба не содержит автора. Это подкреплено правами колонки `reports.author_id`: клиентская роль не может прочитать её или вставить произвольный идентификатор. В Supabase SQL Editor можно безопасно посмотреть **права**, не открывая чьи-либо сообщения:

```sql
select
  has_column_privilege('authenticated', 'public.reports', 'author_id', 'SELECT') as can_read_author,
  has_column_privilege('authenticated', 'public.reports', 'message', 'SELECT') as can_read_message,
  has_column_privilege('authenticated', 'public.users', 'max_user_id', 'SELECT') as can_read_max_id;
-- Ожидается: false, true, false.
```

Ограничение строк по получателю и запрет чтения автора через вложенную связь дополнительно проверяет `supabase/tests/rls.sql` в отдельной тестовой базе. `supabase/tests/notifications.sql` проверяет подпись события, приватность очереди и защиту от повторной доставки. Эти SQL-проверки не создают демонстрационных учеников в рабочей базе.
