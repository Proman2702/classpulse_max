## Устройство проекта

- `miniapp/` — React, TypeScript и Vite. Экраны сгруппированы в `src/features/` по ролям: `auth`, `student`, `teacher`, `inbox`, `shared`. Небольшие модули `src/api/` обращаются напрямую к Supabase, `src/ui/` содержит общие видимые элементы, `src/styles/` — CSS и токены светлой/тёмной темы, `src/lib/` — MAX Bridge, даты и расчёт состояния. `src/hooks/useLoader.ts` загружает данные и обрабатывает ошибки и устаревшие ответы.
- `bot/` — MAX-бот на TypeScript, открывающий Mini App.
- `bot/run.mjs` запускает бота с дополнительными публичными сертификатами из `bot/certs/` для проверенного TLS MAX API v2.
- `supabase/schema.sql` — профили трёх ролей, ежедневные ответы, связи учителей с учениками, заметки, записи на разговор, анонимные жалобы и политики RLS. Обновление идемпотентное и транзакционное; старая таблица `student_requests` сохраняется, но новым интерфейсом не используется.
- `supabase/functions/class-summary/` — серверная функция сводки класса. Проверяет сессию и роль учителя, читает сегодняшние ответы только его учеников и обращается к GigaChat. Ключ GigaChat хранится в секрете проекта Supabase.
- `supabase/functions/classify-report/` — оценка срочности жалобы для авторизованного ученика. При недоступности GigaChat используется `medium`. Общие проверки сессии, HTTP, московской даты и запросы GigaChat находятся в `_shared/`.
- `supabase/functions/link-max/` проверяет подпись запуска MAX и атомарно связывает профиль; `notify/` проверяет HMAC
  события, однократно принимает его и отправляет сообщение через MAX. Конфигурация и реестр событий хранятся в закрытой схеме `private`.
- `miniapp/src/api/max.ts` и `lib/max.ts` обеспечивают автопривязку и приглашение через Bridge с запасным вариантом в браузере.
  `docs/` содержит описание продукта, архитектуры, проверок и сценарий защиты. Docker и `scripts/seed.mjs` — необязательные способы запуска/подготовки демонстрации.
- `miniapp/tests/max.test.ts` — регрессии MAX Bridge; `supabase/tests/rls.sql` — проверки прав и анонимности с откатом данных; `supabase/tests/upgrade.sql` — проверка сохранения старых данных в отдельной тестовой базе.
- `supabase/tests/notifications.sql` проверяет приватность привязки и очереди, подписи событий и защиту от повторов в отдельной локальной базе.

## Реализовано

- Вход и регистрация по email и паролю через Supabase Auth, роли ученика, учителя и психолога. MAX initDataUnsafe используется только для подсказки имени при регистрации, а не для авторизации.
- Ежедневное анкетирование ученика с оценкой, причинами и комментарием. Повторное голосование за день доступно для отладки.
- Учитель видит долю ответивших сегодня, среднюю оценку, карточки учеников с историей последних пяти оценок, поиском, фильтром и сортировкой.
- Учитель может добавить ученика по нику. Доступ к данным ограничен политиками RLS.
- Поддержка ученика: запись к учителю/психологу, анонимная жалоба и переход в MAX по вручную добавленной ссылке профиля. После низкой оценки кнопка сразу открывает форму записи к психологу.
- Учитель отмечает ученика «на контроле», ведёт личные заметки, принимает/отклоняет записи, отмечает состоявшийся разговор и решает жалобы. Психолог видит только обращения к себе.
- Автор жалобы хранится в закрытой колонке `reports.author_id`; клиент не может читать её, фильтровать по ней или получить её через JOIN/вложенную связь PostgREST.
- Интерфейс в стиле MAX: нижние вкладки, списки, аватары с инициалами, шторки и опрос как переписка; мобильная верстка и автоматическая светлая/тёмная тема.
- Сводка сегодняшних ответов класса создаётся по кнопке через GigaChat. В запрос к модели не передаются имена и идентификаторы учеников; ответ не сохраняется в базе.

## Настройка сводки

Развернуть Edge Function `class-summary` с проверкой JWT и добавить серверный секрет `GIGACHAT_AUTH_KEY`. При необходимости можно указать `GIGACHAT_MODEL`; по умолчанию используется `GigaChat-2-Max`. В браузерном `.env` этих значений быть не должно.
